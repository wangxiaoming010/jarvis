## 源码发布检查

源码索引不收录作者联系信息。`npm run release:check` 检查受管理文件中的禁用路径、邮箱与已知凭据模式，不等同于完整隐私审计。完整许可原文位于 `dist/THIRD_PARTY_NOTICES.txt`，不随本次源码提交上传。构建会自动生成该文件，HTTP 和浏览器场景已验证许可入口返回真实文本。

新增生成器测试验证 CRLF、行尾空格、多字节和反引号按原样保留，缺失原文或平台包与父包版本不符时失败。首次回归在旧实现上因未生成许可索引而失败，修改后通过。

## 已修复的审查问题

- 主进程正常退出但后台子进程仍存活时，原逻辑会错误交付成功。新增真实 Node 进程回归用例先出现 `Missing expected rejection`，修复后通过。现在清理进程组并进入中断核实流程。
- 密钥文件先于数据库保存时，崩溃可能导致显示配置与实际外发目标不同。现在每次模型请求前核对完整配置摘要，错配即停止发送，重新保存不继承未确认的密钥。
- 同名规则曾按任务标题相互抑制。现在按规则 ID 关联任务。
- 锁文件创建后再写内容存在空锁窗口。现在完整写入并同步临时文件，再原子建立正式锁；无法确认所有者时保留文件并提供人工恢复步骤。

## 不应外推的结论

- 45 项测试大部分使用隔离模型/执行器网关。浏览器测试也使用 fixture，不等于九家模型服务都已真实联调。
- Codex 实测只证明最小执行和结果入库链路，不证明复杂编程任务、文件产物校验、多人协作或长时间运行已验收。
- Claude Code 当前被安全适配器禁用，不属于已交付的执行能力。
- SQLite 使用 Node 实验性接口；构建存在 Zod 注释解析警告，但本次没有导致失败。
- 尚未进行真实断电、跨进程锁竞争压力、超大历史、恶意 CLI 逃逸或安装包验收。
- 没有读取、迁移或覆盖既有用户数据；没有替换 GitHub 主分支。
