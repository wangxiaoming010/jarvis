# 本地工作台的执行边界

Jarvis 采用一个 Node 服务和一个 SQLite 数据库。React 构建产物与 API 同源，固定使用回环地址。没有外部消息队列、跨机服务或自治权限授予系统。

设计参考了 DeepSeek Super Agent 的概念，但没有集成其运行时、源码、提示词或素材。借鉴点是明确请求或规则授权才工作、后台执行不阻塞对话、只在结果或人工介入时提醒。[研究原型](https://github.com/deepseek-ai/dsh-superagent-prototype)

## 模块所有权

| 模块                      | 责任                                       |
| ------------------------- | ------------------------------------------ |
| `shared/domain.ts`        | 数据结构与边界校验，前后端共同读取         |
| `server/http.ts`          | 本机会话、来源检查、请求解码与静态文件     |
| `server/workspace.ts`     | 消息投递、任务状态、审批、调度、通知与规则 |
| `server/store.ts`         | SQLite 事务与私密配置存储                  |
| `server/ports.ts`         | 模型和执行器的领域接口                     |
| `server/integrations.ts`  | 外部模型协议与本机 CLI 进程                |
| `server/instance-lock.ts` | 同一数据目录的实例互斥                     |
| `web/`                    | 工作台视图、表单与服务器状态呈现           |

SQLite 保存单个经 schema 校验的工作区聚合。它让单用户事务简单，但每次写操作会重写整个聚合，不适用于大型历史记录。此阶段接受这个限制，不宣称可支撑大规模部署。

## 任务闭环

```text
待批准 → 排队 → 运行 → 待验收 → 人工接受
                    ↘ 失败 / 中断 / 取消
```

审批保存当前任务版本、工具、模型选择、专用目录、固定 `workspace-write` 范围和有效期。客户端不能扩大授权。执行器只接受服务端选定的配置，模型只能提出任务建议。

每次运行有独立 `runId`，迟到结果不能写入另一轮任务。取消要确认主进程关闭和进程组消失。正常主进程退出但仍有后台进程时也不能作为成功交付。无法确认时进入中断，恢复要求人工填写核实说明并重新批准。

结果文本有摘要，只有人工接受才将任务标记为完成。文本摘要不等于文件清单校验、独立验证、目标项目应用或 Git 合并。

## 模型请求

模型和执行器是不同边界。主会话模型负责理解和提案，本机 CLI 负责批准后的执行。对话密钥不放入 CLI 环境。

DeepSeek 开启思考并使用任务提案工具时，把可见历史封装为新一轮输入上下文，不回放缺少 `reasoning_content` 的历史工具轮次。这是单轮提案实现，不是保留完整推理历史的多轮工具会话。[协议依据](https://api-docs.deepseek.com/guides/thinking_mode/)

模型地址、模型名和密钥一起保存，并用摘要与数据库设置绑定。文件与数据库在异常中断后不一致时，拒绝外发请求，而不是使用界面未显示的目标地址。

## 后续迁移门槛

完整替换仍需要独立长期目标、可追踪委派接责、原生交互卡、版本化事实和交付证据、工作树协调、历史数据导入及回滚、桌面运行环境打包。这些功能尚未完成，不用近似字段宣称已经对齐。
