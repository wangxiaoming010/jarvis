# 整体架构

```text
Tauri / React 客户端
       ↕ HTTP + 认证 WebSocket
Fastify / SQLite
       ├─ 每 Bot 独立注意力 → 主会话 → 目标、委托与执行调度
       ├─ 看门狗、持久事件、共同事实与交付记录
       ↕ 独立凭据的 Bridge WebSocket
Node.js 本地 Bridge
       ↕ stdio
Codex app-server / Claude Code stream-json
```

每个 Bot 独立沟通、维护记忆并负责工作。群组组织对话，不设置群级决策模型。平台提供持久账本、状态约束、事件投递和执行协议，不替 Bot 作业务判断。

## 模块职责

| 模块                   | 职责                                              |
| ---------------------- | ------------------------------------------------- |
| `apps/desktop`         | React 交互、声明式卡片和 Tauri 生命周期           |
| `apps/desktop-runtime` | 安装包内服务与 Bridge 的启动、连接和退出          |
| `apps/server`          | Fastify API、SQLite、注意力、Bot 协调与工作管理   |
| `apps/bridge`          | 本机 CLI 检测、会话恢复、执行、进度与原生权限交互 |
| `packages/shared`      | 实体类型、协议、Schema 与卡片校验引擎             |

`apps/server/src` 按职责分组：根目录是入口与基础设施（`index.ts`、`app.ts`、`runtime.ts`、`store.ts`、`config.ts`、`local-service.ts`）；`bot/` 是 Bot 主会话、提示词组装、上下文压缩、跨对话工具、委托与注意力排序；`memory/` 是长期记忆与后台记忆整理；`models/` 是模型调用、模型与执行设置；`work/` 是任务契约、流水线、资源、看门狗、目标、交付物与项目事实；`host/` 是原生交互请求与卡片服务。测试按应用放在 `tests/server`、`tests/bridge`、`tests/shared`、`tests/scripts` 与 `tests/e2e`，真实环境验证脚本在 `scripts/smoke/`。

## 运行与身份边界

安装包包含 Node.js、后台和 Bridge。Tauri 通过 `local_service` 命令获得本机连接，随机凭据以受限权限保存。服务只监听 loopback，端口冲突时另选端口，同一数据目录禁止重复启动。

客户端和 Bridge 使用独立令牌。当前所有者通过认证 API 管理 Bot 和设备，群消息不能修改设备绑定或审批策略。Tauri 不把通用 shell 或文件系统命令开放给聊天内容。当前模型适用于本机单所有者，尚不支持多人或公网部署。

关闭窗口仅隐藏到菜单栏／托盘，后台继续运行；明确退出才关闭后台。父进程管道关闭时，内置后台停止 Bridge 并关闭数据库。源码与安装版数据目录分开，见[故障排查](troubleshooting.md)。

## 消息与注意力

默认入口由 `createAttentionModel`、`createCoordinatorModel` 和 `BotCoordinator` 组成。人类与 Bot 群消息事务性写入其他成员的持久收件箱，单聊只投递给关联 Bot。普通群消息先进行独立、无工具的注意力判断；忽略不会启动主会话或写入记忆。私聊、直接 @、人类明确回复自己及本人的任务事件跳过判断。

每个 Bot 串行提交状态，不同 Bot 可并行。人类指令、执行结果和阻塞事件优先于普通进展；高优先级指令可以中断后台模型等待，已提交工具结果会复用。这不会取消实际 Worker。

每条消息为全部 N 位接收 Bot 独立随机分配 1 至 N 的唯一顺序权重，并将关注机会按相邻 200–400 毫秒错开，不限制为两位 Bot。权重和开始时间持久保存，重试或重启不重新抽签。注意力判断与主会话同时获得自己和同伴的权重、处理状态，以及原消息之后新增的同群交流；顺序只供结合上下文判断，不强制等待上一位完成，也不限制靠后的 Bot 回应。私聊、直接 @ 和人类回复自己的注意力跳过规则保持生效，实际执行任务仍按原有资源规则并行。

私聊和群聊共享同一 Bot 身份、记忆和工具能力；差异主要在消息投递与注意力入口。BotConversations 提供本人所在对话的完整成员概览、跨对话历史检索、分页读取和发送能力，访问时重新校验成员归属。BotMemory 支持从任意可访问消息提取带来源的本人记忆；注意力被忽略的原始消息仍可事后读取。跨群发送保留真实 Bot 发送者和实际 @ 对象，只携带 Bot 决定发送的内容，继承协作链停止与预算规则，并以来源、目标及内容生成稳定标识防止重试重复发布。

主会话支持 OpenAI 兼容工具调用和 Anthropic 原生协议。近期消息、记忆和任务摘要内联，完整记录按引用及偏移读取。`coordinator_turns` 和 `coordinator_calls` 保存事件处理与工具结果；数据库副作用与对应调用结果原子提交，重启不重复已提交的派工。

BotContext 自动整理旧对话和过长的工具处理记录，计入工具定义并预留回答空间。摘要按 Bot 保存、带来源引用且可恢复；原始消息、工具收据和被折叠的上下文快照保留，可通过 read_context 等工具分页读取。摘要独立于长期记忆，不能代替授权或验收证据。具体预算、失败退化与模型容量限制见[持续工作架构](super-agent.md#上下文管理与自动压缩)。

## 目标、执行和协作

`work_goals` 独立记录负责人、验收条件、要求版本、下一行动、等待、截止和投递位置。目标可以离线建立，也可以完全通过委托完成。`tasks` 表示执行任务，`worker_runs` 表示具体租约、设备、会话、版本和真实结果。执行完成后进入待验收，不能直接关闭显式目标。

任务管道承载持续工作上下文。同一任务变更或返工沿用管道；明确相关的下一任务可以复用，目录相同不自动合并。原生会话按管道、Provider、设备保存。续接只发送尚未确认的新要求，切换 Provider 时显式交接。

`bot_delegations` 保存委托、接受、交付、退回与取消，@ 消息本身不表示接单。目标和任务可按所有者的新指令接续到另一对话，结果只发往当前路线。共享项目保存版本化需求、决定和接口事实，范围须显式授权，不合并 Bot 私有记忆。

交付物记录真实文件、Git 差异或执行报告的版本和摘要，状态分为产出、验证、接受和实际应用。验收重新核实内容、要求版本及共同事实；JSON 可解析只证明语法。完整状态机与证据规则见[持续工作架构](super-agent.md)。

## 执行与恢复

默认每位 Bot 最多 2 个执行、每台设备最多 4 个。写执行按设备保守串行，未知执行保留占用；只读任务拒绝原生写入和提权申请。Git worktree 为干净项目建立独立副本并保留差异，不自动合入。资源占用与 cwd 不构成完整文件系统隔离。

Bridge 使用各 CLI 自身的登录和配置，只回传公开文本、工具活动和结构化进展，不回传隐藏推理。原生请求绑定任务、设备、请求 ID 和当前 lease；停止、断线、任务结束及重启使待回答请求失效。详见[原生权限交互](native-interactions.md)与[Claude 接入](claude.md)。

停止先持久记录意图并请求原生中断，等待实际执行终止。已派发但未确认结果的执行标为未知，不自动重放；尚未派发的队列可以在设备上线后继续。看门狗区分心跳、真实进展、等待、阻塞和待验收，只产生事实与复核事件，不自行重跑任务。

## 接口与存储入口

HTTP 路由定义在 [app.ts](../apps/server/src/app.ts)。业务 API 要求客户端认证，`/health` 用于无凭据健康检查；WebSocket 使用各自的认证握手。

| 入口                                                     | 用途                                   |
| -------------------------------------------------------- | -------------------------------------- |
| `/api/snapshot`                                          | 本机状态快照，不包含模型密钥           |
| `/api/messages`                                          | 以消息 ID 幂等写入并触发 Bot 处理      |
| `/api/tasks/:id/status` 及 `change`、`stop`、`resume`    | 任务观察与所有者操作                   |
| `/api/goals/:id/status` 及 `stop`                        | 持续目标观察与停止                     |
| `/api/native-requests/:id/reply`                         | 原生问答和权限回复                     |
| `/api/groups/:id/cards`、`/api/cards/:messageId/actions` | 卡片发布与受校验的宿主动作             |
| `/events`                                                | 认证后通知状态失效，客户端重新读取快照 |
| `/bridge`                                                | 独立凭据的设备连接、执行命令和租约事件 |

SQLite 启用外键与 WAL。`apps/server/migrations/` 保存按序应用的完整历史；通过新增迁移升级已有数据，不删除旧迁移。备份和恢复步骤见[数据恢复](troubleshooting.md)。

应用不使用群级路由；未配置主会话模型时保留明确 @ 的直接执行方式。

## 当前范围

本地全量快照适用于小规模历史，尚无大规模分页同步。目标树总预算、统一资源授权、跨目标等待与资源死锁检测，以及外部副作用的逐操作幂等恢复仍待完善。当前预算主要约束消息协作链和单任务，不能视为完整成本预算。

远程配对、多人权限、自动合入、自动更新及 Windows / Linux 发布包不在已验证范围。源码与浏览器测试不等于真实模型或桌面发布验证；验证和发布步骤见[贡献指南](../CONTRIBUTING.md)与[发布指南](releasing.md)。
