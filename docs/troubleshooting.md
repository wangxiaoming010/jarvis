# 故障排查与数据恢复

## 应用和服务无法启动

源码开发先运行 `npm ci`，检查 Node.js 是否至少为 22.18。`npm run desktop` 还需要 Rust 与 Tauri 前置工具链；只检查网页界面可用 `npm run dev`。

开发端口默认是服务 `4310`、界面 `1420`。启动器拒绝连接已占用的服务端口；先停止旧开发进程，或设置 `PORT` 和 `CLIENT_PORT` 后重启。安装版使用自己的本机连接，端口冲突时会另选端口。

安装版界面提供重试连接。macOS 的后台诊断日志位于 `~/Library/Application Support/com.openbot.desktop/service.log`。分享日志前删除凭据、个人路径和任务内容。

## 模型不回复

在设置中确认服务地址、Key、模型名称和注意力模型。设置页保存的本机配置优先于 `.env` 初始配置，修改环境变量后需要重启。

普通群消息可能被某位 Bot 的注意力判断忽略；私聊、直接 @ 和明确回复自己的消息会跳过该判断。注意力调用失败会显示可重试错误。重试失败的 Bot 不会重放其他 Bot 已完成的回复。

## 本地执行能力不可用

先在独立终端确认 `codex` 或 `claude` 能运行，且其 Provider、登录和网络配置可用。必要时设置 `OPENBOT_CODEX_PATH` 或 `OPENBOT_CLAUDE_PATH` 并重启 Bridge。CLI 检测通过只说明配置就绪，不保证后续模型请求一定成功。

Codex 检查分为版本、启动握手和账号状态三个阶段。版本检查限时 10 秒，启动握手限时 30 秒；握手成功后，账号状态有独立的 10 秒限时。Codex 和 Claude 的检查异步进行，不会互相阻塞响应处理。提示“需安装”表示没有找到可执行文件；版本检查失败、执行权限不足、启动握手超时和账号状态超时会分别提示。超时本身不能证明未登录，也不能证明插件或 MCP 有问题。

遇到启动握手超时，先确认应用使用的 CLI 路径与终端中正常运行的是同一个，并确认该 CLI 的 `app-server` 能启动；账号状态超时则检查该 CLI 的账号配置。配置检查只进行握手和 `account/read`（不刷新令牌），不会创建任务、调用模型、登录或修改 CLI 配置。不要直接分享 `auth.json` 或包含账号信息的完整协议输出。

Bot 可以在设备离线时接下目标，实际执行等待匹配设备上线。等待权限或提问时，在原聊天的系统卡片中处理；已失效卡片不能继续授权。Claude 的具体限制见[接入说明](claude.md)。

## 任务停滞或连接中断

查看活动记录中的目标、任务状态和真实进度。执行心跳不是任务进展；结果未知也不代表未执行。

已派发但未确认结果的工作不会自动重跑。先检查实际文件或外部操作，再明确要求 Bot 继续或停止。需要所有者决定的目标会暂停后续派发，新的明确指令才能恢复推进。

## 备份、恢复与升级

源码开发的数据默认在根目录 `.data/`，安装版使用系统应用数据目录；macOS 为 `~/Library/Application Support/com.openbot.desktop`。两者不自动共享数据。原生 Agent 的会话历史由各 CLI 单独保存。

1. 在菜单栏／托盘选择退出应用；只关闭窗口会保留后台。开发环境先结束启动器。
2. 复制整个数据目录作为备份，保留文件权限。不要只复制正在写入的 SQLite 主文件，WAL 中可能还有已提交数据。
3. 恢复时保持应用退出，用备份替换对应数据目录，然后启动相同版本或兼容的新版本。

升级会自动应用新增 SQLite 迁移。数据库升级后不要直接用旧版应用打开；需要回退时恢复升级前的完整备份。不要删除历史迁移、手工清空任务表或把数据目录提交到 Git。
