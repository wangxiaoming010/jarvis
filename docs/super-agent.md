# Bot 持续工作架构

每个 Bot 都有独立的对话协调状态，负责沟通、记忆、任务安排和结果验收。群组不调用群级路由模型。Codex 与 Claude Code 是本机可调度的执行资源，Bot 的 provider 字段保存所有者选择的执行工具，具体执行使用 task_workers 中的 provider。创建及执行设置可选择工具，派工沿用该选择；所选工具离线时排队，不自动换用其他工具。有排队、运行或待验收任务时，须先完成或停止任务再修改执行设置。

## 生命周期

工作区新增群组、成员、资料、消息、实时状态和记忆索引工具，详见 [Bot 工作区工具](bot-tools.md)。查询直接读取当前数据库；管理操作绑定调用者身份并校验所有者事件、成员权限和未结束工作。当前群退群成功后会持久结束本次事件，避免在已退出的对话继续回复。

- 关闭桌面窗口隐藏界面，后台、Bridge、消息处理和任务继续运行。菜单栏／托盘可以打开窗口或明确退出；macOS Dock 再次打开也会恢复窗口。
- 明确退出应用才关闭后台和本地执行。电脑休眠或离线期间不保证执行，重启后恢复持久记录。
- Bot 可以主动发现相关问题并在预算内发起静默只读调查。对既定目标可以安排审查和返工；执行权限继续由原生宿主控制。

## 事件与主会话

人类群消息事务性投递到每位成员的持久收件箱；Bot 群消息也投递给其他成员，单聊仅投递给关联 Bot。每个 Bot 全局串行消费事件，不同 Bot 并行。普通群消息先经独立无工具的注意力模型，仅返回 `{"wake":true}` 或 `{"wake":false}`，false 不进入主会话、不发言或写记忆；私聊、直接 @、人类明确回复自己及本人任务事件绕过判断。Bot 之间普通的引用／回复关系仍须通过注意力判断，不会因为被引用就自动唤醒。已唤醒的主会话可调用 stay_silent 明确结束当前事件，不发布任何消息，也不取消进行中的工作；尚未核实的执行结果仍须按验收规则处理。Bot 可互相 @ 请求协助或回传结果，实际唤醒计入持久预算并限制回复深度，避免循环。判断失败有限重试并保留可重试错误，不能伪装成忽略或默认放行。

主会话支持 OpenAI 兼容的 Function Calling 和 Anthropic 原生工具协议；DeepSeek 请求关闭思考模式。平台提供任务执行、计划、跨对话接续、同事委托、证据验收和记忆治理工具。主会话没有任意文件读写或 shell 工具；平台提供产物校验等受约束操作，执行授权仍由原生宿主管理。每次 start_worker 立即返回，任务的原生执行不阻塞对话。

群消息的接收者按消息随机取得不同的顺序权重，相邻关注机会错开 200–400 毫秒。`message_attention_order` 持久保存本次分配和开始时间，重试与恢复复用同一分配。`responseOrder` 将自己的权重、同伴权重和实际处理状态提供给注意力及主会话，`messagesSinceSource` 提供触发消息之后已发生的同群交流，并在模型调用前更新。它们是判断是否参与和如何接话的辅助信息，不是强制轮流、固定主持或唯一发言权；原有直接点名规则和异步执行继续适用。

同一 Bot 的状态提交保持串行，收件箱按优先级处理：直接人类指令、执行完成、普通人类消息／明确阻塞、委托、其他复核、普通进展。高优先级人类指令可中断正在等待的后台模型请求；被中断事件重新排队，已提交工具结果复用，过期进度丢弃。这里中断的是协调判断，不会取消实际 Worker。

coordinator_turns 保存每个事件的上下文、模型答复、调用轮数和处理状态。执行工具前先保存模型请求；工具副作用和 coordinator_calls 的结果在同一 SQLite 事务中提交。中断后先回收已提交结果，避免重新启动同一工作。最终对外回复与事件确认也在同一事务中提交。

主会话是一套可恢复的身份、记忆、事件序列和任务索引，而非无限增长的 API 上下文。同一 Bot 跨私聊和群聊保持连续身份：成员概览、相关历史、本人记忆和任务摘要内联，完整消息通过检索、分页和稳定 ID 按需恢复。Bot 可以读取自己当前所在的所有对话，也可以从其中任意消息提取记忆；其他 Bot 的私聊和本人未加入的群不可访问。本人理解历史与向其他参与者披露历史是不同的决策，不自动转发整段私聊。共享项目的显式授权与工作归属规则独立保留。

## 上下文管理与自动压缩

BotContext 在每次主会话请求前构建受预算约束的视图，适用于私聊与群聊。当前按 UTF-8 字节数保守估算 token，默认总容量 65,536，预留 8,192 用于回答、2,048 用于估算误差，并计入完整工具 Schema。可通过 OPENBOT_CONTEXT_TOKENS 配置服务的容量预算；它不是对所选模型真实容量的自动检测，使用更小上下文的服务需要相应调整。

旧对话保留最近 12 条消息的近期视图，长消息可按引用读取原文；更早内容较小时直接补充，超过约 2,000 估算 token 后增量整理为带来源范围的工作摘要。每次模型请求最多推进两批，每批最多 32 条、摘要输入保持有界。尚未整理的历史明确标记范围和数量，完整内容始终可检索；单条长消息只提供摘录时也标明需要回查原文。bot_context_history 按 Bot 和对话保存摘要、已覆盖消息和来源摘要值，重启复用；原文发生变化则失效重建，处理较早事件时不套用未来摘要。

一轮处理中工具结果累积超出预算时，按完整的调用与结果成组压缩旧内容，尽量保留最新一组。单组结果过大也可归档成工作摘要。身份规则、当前请求与当前任务约束保持有效；大型背景索引可替换为指向 bot_context_inputs 不可变快照的引用。coordinator_turns、coordinator_calls 与原始消息不被压缩视图覆盖，read_context 按本人、当前成员归属、轮次和调用标识分页取回真实工具收据或快照。bot_context_compactions 保存摘要并避免恢复时重复生成；压缩不改变工具执行账本或重新执行工具。

整理使用已配置的主会话模型，独立调用且不提供工具。摘要失败时退化为明确标注不完整的原文摘录；中断结果不提交。摘要生成后再次刷新实时成员、任务和同群新增消息，再检查预算。极端情况下，必要身份、当前请求与任务约束本身超过容量时保留原始记录并报告失败，不静默裁掉这些约束。

工作摘要与长期记忆分开，既不是新的所有者指令，也不授予权限或证明验收通过；需要精确事实与证据时回查原文。Bot 自己决定是否进一步用 remember 整理为带来源的事实。这里管理 Bot 主会话的上下文，原生 Codex／Claude 执行会话的容量与压缩仍由相应工具管理。

## 任务与执行

work_goals 表示 Bot 接下的持续目标，独立保存负责人、验收条件、要求版本、下一行动与投递对话。tasks 是目标下的执行任务；task_specs 与 task_changes 保存执行要求，task_workers 保存执行选择、资源占用、父任务和执行验收状态，worker_runs 保存每次原生执行的租约、设备、会话、要求及项目版本和真实输出。

同一 Bot 默认最多 2 个执行，同一设备最多 4 个；可通过 OPENBOT_WORKERS_PER_BOT 和 OPENBOT_WORKERS_PER_DEVICE 配置。resourceMode 分为 read、exclusive、worktree。设备上的写执行保守串行，即使声明不同目录也不能同时写；未知执行保留其写占用，直到所有者明确核实原任务。只读执行不占写名额，同一路径的只读任务可以并行，Bridge 拒绝其写入、命令和提权请求。原生只读沙箱仍可能运行沙箱允许的只读命令，不将它描述为禁止一切命令。

worktree 要求指定干净的 Git 项目，平台按管道创建独立 detached 工作副本，并将原生 cwd 指向副本。结果保留副本位置、基础提交、真实差异和未跟踪文件清单，不自动合入原项目，也不自动删除交付副本。原生审批仍然适用；cwd 和 worktree 并不构成完整文件系统沙箱。外部程序的并发写入、自动合入与冲突解决不在当前资源占用协议内。

每项任务先分配持久工作管道。管道表示一段持续工作的上下文，由 Bot 负责；相同目录或相近技能不能作为复用依据。同一任务调整或返工使用 update_task / continue_task；明确相关的下一项任务可以通过 start_worker 的 pipelineId 复用管道，独立目标默认新建。平台拒绝跨 Bot、未关联对话或已归档管道，未核实的未知执行不能通过另建任务绕过。

task_conversations 记录显式关联，task_routes 选择唯一结果投递位置。所有者在当前群或私聊要求接续后，Bot 用 link_task 关联自己的已有任务；改变要求与验收必须在当前投递对话中进行。关联不创建重复执行，不复制其他对话的聊天，也不把结果广播给所有关联群。原生会话和任务负责人保持连续。当前版本为本机单所有者授权，不能直接视为多人群的访问控制。

task_pipelines 与 task_pipeline_bindings 保存管道和任务归属，pipeline_sessions 按管道、Provider、设备保存原生会话。同一管道一次只执行一项工作，待验收期间仍占用管道；完成验收才放行下一项任务。不同管道仍受设备容量和资源占用约束。

同一任务可以跨多次 Worker 执行接力。同 Provider、同设备恢复对应原生会话；首次切换 Provider 时新建会话，显式附带目标、上一轮产物和新要求，切换回来仍能恢复该 Provider 原有会话。原生会话历史不跨 Provider 复用。管道中的新任务必须完整发送本次要求，不能套用上一任务的要求接收游标。父任务可以创建支持性子任务，子任务未完成验收时不能接受父任务；子任务通过验收后会通知父任务协调者。

task_contracts 兼容原有执行任务的验收条件、下一行动、等待条件、下次检查、截止时间、执行预算和计划代次。新持续职责使用下述 work_goals 生命周期。新目标默认以工作说明作为验收项，实质工作应给出明确 criteria。plan_task 维护计划；到期只产生一次持久复核事件，不直接执行、重放未知操作或恢复停止工作。截止提醒独立于下次检查时间。默认每任务最多 12 次执行，增加预算必须来自新的人类请求。

Worker 返回完成时，执行任务进入 reviewing，显式目标仍由负责人独立推进。主会话比较最新要求与实际证据，调用 finish_task 验收，或 continue_task 安排后续处理。每个验收项必须引用本次执行结果、同一租约汇报或已验收委托的真实文本，记录到 task_acceptance；旧要求版本和虚构引用不能验收。文本可追溯不等于结论一定正确，Bot 仍需按目标安排产物检查或独立验证。原生结果原样保存在执行记录中，对外答复由 Bot 统一组织。

## 身份与实时状态

Bot 和群组在创建时自动分配固定 UUID；改名、修改资料、切换执行工具、变更成员和服务重启不改变 ID。删除后重建的同名群组使用新 ID，不接续已删除群组的身份。名称仅作为可变的显示标签。

`get_self` 由平台绑定调用者身份，实时查询本人的资料、执行状态和当前加入的对话，不接受替换 Bot 身份的参数。`list_conversations` 实时列出已加入的群组和私聊；`get_conversation(groupId)` 按固定 ID 查询当前群名、描述、成员身份和本人的工作概览，不读取聊天正文。每次结果包含 `observedAt`，仅代表本次查询时刻。删除群组或移除成员后，对话立即从对应 Bot 的列表消失；旧 ID 不会被自动替换为同名的新群组。

回答当前身份、成员归属等问题前，Bot 应先调用实时工具。历史聊天、记忆、摘要和旧工具回执不作为当前成员关系的依据；成员列表在上下文压缩中被归档时，明确要求重新查询实时列表，而不是将历史快照当作现状。每轮保留不参与压缩的实时状态来源提示。原有长期偏好等记忆保持可追溯，不因群组删除而清空 Bot 的全部记忆。所有查询均检查当前成员权限，未加入、已离开或已删除的对话不可访问；查询失败本身不区分退群与删除。

## 同事委托与记忆

bot_delegations 是同事之间的协作账本，没有群级决策者。delegate_task 提出目标、验收条件和期限；接收 Bot 用 respond_delegation 明确接受或拒绝，接受后创建自己负责的任务。协作方验收自己的执行后提交，发起方通过 read_delegation 和 review_delegation 接受或退回返工；父任务必须先解决所有尚在进行的委托才可验收。禁止同一委托链回委托给上游，限制同时待处理委托数量，并继承现有执行预算。

停止父任务递归撤销委托并停止下游；协作方停止自己的任务立即通知发起方，执行失败也通知发起方核实。期限到达时持久记录过期并请求停止下游，不把停止请求等同于执行已终止。父任务转到私聊后，其委托结果与复核沿已授权投递路线回到父负责人，协作方保留自己的工作对话。

BotMemory 在 SQLite 中按当前问题检索相关旧事实，兼顾重要性与近期性；recall_memory 可主动检索。remember 保存 user、inference、worker 来源与有效期，精确重复内容合并；replacesId 明确更正，forget_memory 失效并保留修订记录。推断不能静默覆盖用户明确事实。Bot 可跨自己所在的对话检索本人的 Bot 级和群级记忆；群级记忆仍保留原群标识和披露意图，不与其他 Bot 合并。remember 可指定已检索消息的 sourceMessageId，按真实发送者校验 user 来源，支持在另一个聊天中整理旧事实。更正群级记忆时需保持原群范围，遗忘可跨本人可访问的对话进行。任务状态与成员归属读取实时业务数据，不复制成长期事实。当前为词项检索和模型决定的显式记忆写入；完整历史不因注意力忽略而丢失，但尚未实现独立的后台记忆整理、短中长期分层、语义去重或自动裁决事实冲突。

## 停止与恢复

停止标记、租约、要求版本和原生审批继续由平台强制执行。停止父任务也停止子任务。停止与完成竞争时保留真实执行结果，但阻止自动返工和后续新执行。

服务或 Bridge 断开时，已派发执行记录标为 unknown，并通知所属 Bot；不会自动重放可能已产生副作用的操作。排队任务保留。只读核实与明确续接可通过正常任务机制进行。

每个 Bot 有自己的持久任务台账。task_health 保存观察状态、真实活动时间、执行心跳及异常说明；主会话收到当前对话任务和跨对话的本人任务索引，精确内容按任务引用读取，由 Bot 判断相关内容的适当披露范围，不自动转发原文。看门狗维护事实和异常线索，Bot 负责目标、处置与结果验收。

Bridge 每十五秒发送当前租约的执行心跳；心跳只证明执行连接活跃，不当作任务进展。独立看门狗每分钟检查持久状态：超过五分钟没有真实活动时，心跳仍新鲜标为 stalled，心跳超过九十秒标为 unresponsive。等待设备、原生问答或授权、明确受阻、待验收、连接中断后结果未知分别记录。相同未变化活动只生成一次复核事件，正常等待不视为异常；观察状态不会直接将任务判失败、杀进程或自动重跑。主会话/API 失败保留诊断和任务状态，后续监控可重新检查仍待验收的结果。

Worker 的公开 commentary 和结构化 progress / milestone / blocked 汇报写入 worker_reports，按任务、当前租约与内容去重。普通汇报合并，通常每分钟至多通知 Bot 一次；明确里程碑和阻塞可立即通知。原始输出片段和心跳不逐条调用模型。汇报是待核实材料，既不等于完成，也不等于验收。完成或停止先于进度处理时，过期汇报丢弃；模型处理期间收到真实结果，也会阻止迟到的进度回复与操作。

普通进度与里程碑事件只允许读取状态，不允许创建、调整或停止任务、写记忆或发布群消息。明确阻塞由 Bot 判断是否需要所有者决策。日常交流以尊重、诚实、善意和同理心为基础：用户向自己或全群问好、感谢、告别或表达需要回应的情绪时，给予自然友好的回应；按对象区分同事的对话与工作归属，避免互相回礼的循环。任务接收、管道选择、监控、等待和「我不插话」均不发言，不设置任意字数上限。

## 兼容与验证

010_bot_coordinators.sql 与 011_empty_start.sql 扩展现有 SQLite；只有未经使用的旧默认群会被移除，其他 Bot、消息、任务、摘要和原生会话历史均保留。012_bot_attention.sql 保存独立注意力判断与 Bot 唤醒预算。013_task_pipelines.sql 增加工作管道、原生会话映射、任务健康与 Worker 汇报，将历史协调任务分别迁入独立管道并保留原生会话，不合并无关历史。014_durable_work.sql 增加任务契约、证据、对话关联、委托、记忆修订和工作副本记录；升级保留既有数据，历史任务兼容原有验收条件。

旧群路由／单次 JSON 对话接口仅保留供兼容和回归验证，默认桌面与源码入口使用每 Bot 的协调模型。人类所有者与群内 Bot 是独立身份；失败的 Bot 收件箱可单独重试，不重放其他 Bot 的回复。主会话模型可在运行时选择 DeepSeek、OpenAI-compatible 提供商或 Anthropic 原生工具协议，密钥单独保存在本机权限受限文件中。未配置模型时仍支持旧的明确 @ 本地执行方式。

自动测试覆盖协调、注意力、生命周期，以及 tests/server/durable-work.test.ts 和 tests/server/durable-migration.test.ts 中的持续目标、跨对话委托、证据、到期检查、抢占、真实 worktree 和旧数据升级。原生协议测试验证只读执行拒绝写申请。真实只读链路验证：scripts/smoke/coordinator.mjs、scripts/smoke/attention.mjs。运行真实验证会使用已配置模型和本机 Provider，独立数据库及资源文件在临时目录中创建并清理。

## 独立目标与持续推进

create_goal 在没有 Bridge 或 Worker 时也能登记责任。start_worker(goalId) 按需建立执行任务，设备离线时保留排队记录，上线后派发。负责人可以只通过 delegate_goal 委托、检查交付和 finish_goal 完成责任，不要求负责人先运行自己的 Worker。finish_task 只接受执行结果，不能关闭显式目标。没有 goalId 的 start_worker 保留一次性旧调用语义，创建兼容目标并随执行验收结束；实质持续职责应明确 create_goal。

plan_goal 保存下一行动、下次检查、截止、结构化 waitFor 或 needsHuman。waitFor 支持本目标任务、可见目标、同事委托、项目事实、交付物状态、人类新消息和绝对路径文件的出现／消失。条件满足会持久投递一次，已经满足的条件也能识别；条件数组按任一满足唤醒处理。文件存在性由本地代码检查，不启动 Worker 或调用模型。

所有未结束且未等待所有者的目标都有后续检查时间，默认五分钟。运行、排队、待验收的执行和在途委托依靠自身事件，正常等待不反复调用模型；截止仍独立触发。连续三次无人安排有效后续行动时进入 needs_attention，写明需要所有者决定的原因，不继续后台循环。仅改写下一行动文字或检查时间不重置无人处理计数。

needsHuman 和到期升级设置 owner_wait：后台不能创建或恢复执行，也不能用旧的人类来源伪造新授权；已排队执行也暂停派发。新的人类要求才能解除该等待。停止目标递归取消下游目标、委托与执行，实际执行仍等待原生取消确认。重新接下已结束目标需要 reopen_goal 和当前版本，生成新要求版本，旧交付证据不能直接复用。

## 共同事实与版本依赖

work_projects 和 project_groups 显式界定共享项目范围，不绑定某个目录。每个 Bot 保留独立记忆与判断，项目只保存共同引用的需求、决定和接口约定。propose_project_fact 创建有来源的版本提案，expectedVersion 防止相互覆盖；confirm_project_fact 仅接受本轮人类明确确认，重复确认不覆盖首次确认来源。旧提案、已确认版本和当前生效版本分别保留，建议不会自动变成定论。

每个 Worker 启动时捕获确认事实及版本，并把确切内容交给原生执行。验收检查运行时快照与当前事实；修改已有约定或新增确认要求都会让旧执行证据失效。项目变更会通知受影响目标的负责人重新安排，并保留后续检查，不擅自替负责人修改交付结论。

跨对话目标接续与项目共享是两个操作：link_goal 迁移该目标及关联执行的结果路线；项目目标需要先由所有者 share_project 到目标对话。共享项目才允许同事读取项目交付物；明确委托也能在所属对话内授予接收方读取相关产物的范围。不会复制其他对话原文或合并 Bot 私有记忆。

## 交付物、验证与应用

register_artifact 将真实文件、Git 工作副本或原生执行报告登记为版本化交付物。普通文件记录内容摘要，Git 交付记录基础提交、实际变更文件、未跟踪文件和删除项；报告引用真实运行结果。相同交付物修订时保留 artifact_history，旧版本的校验和接受不能自动迁移到新版本。

状态依次为 produced、verified、accepted、applied。校验、负责人接受和目标项目实际采用分开记录；每次状态推进及目标验收均重新检查当前内容和项目依赖。独立验证要求另一个任务、独立原生会话、实际传入的交付版本摘要及已验收结果引用。人工复核必须来自新的人类确认。JSON 解析由本地代码实际执行，但只证明语法，不代表功能或测试正确。

显式目标默认 verification=reviewed，每项验收证据都需要独立执行或人工复核；只有验收标准确实限于内容／格式检查时才采用 content。嵌套委托会递归核实其交付，不能通过层层转述绕过复核。finish_goal 不要求本人的 Worker 成功，但要求每项条件对应当前接受的交付版本，且所有在途执行、未知结果和未解决委托都已处理。

record_application 不修改或发布文件，只核对登记时确定的目标位置是否与接受的交付清单匹配，并保存应用回执。Git 目标必须仍继承基础提交；目标内容后来变化时不能继续拿旧的 applied 状态通过验收。delivery=applied 的目标必须达到该状态，不能把“副本已完成”说成“原项目已完成”。默认仍不自动合入、推送或发布；原生写操作保留现有授权流程。

015_work_ownership.sql 将已有执行与委托迁入兼容目标，保留原任务 ID、对话、记忆、原生会话和在途状态。新事件、订阅、事实版本、产物版本、验证回执和目标验收均在 SQLite 持久保存。重启不会自动重放未知执行。活动记录和概览可以显示没有 Worker 的目标、下一行动、待决策原因和交付阶段。

认证接口：GET /api/goals/:id/status 返回目标、关联执行和交付物；POST /api/goals/:id/stop 停止目标。活跃显式目标阻止直接删除其当前群组，需先接续到其他对话或停止。tests/server/work-ownership.test.ts、tests/server/durable-migration.test.ts 和 tests/e2e/work-goals.spec.ts 覆盖这套生命周期与升级流程。
