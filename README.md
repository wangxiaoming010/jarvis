# Jarvis

数字员工工作台，支持纯本地运行，也可通过 SSH 私有访问云端、由 Mac 执行。用会话讨论需求，用任务记录执行，用交付物验收结果。

**当前是独立重写的 0.1 开发版，不是完整替代版本。** 它使用独立数据目录，不导入或覆盖既有工作区。完整功能对齐、数据迁移和桌面安装包尚未完成，见 [交付状态](docs/status.md)。

## 设计理念：借鉴 DeepSeek Super Agent

Jarvis 的工作流设计借鉴 DeepSeek Super Agent 的思想：减少用户盯进度、反复催促和处理无效通知的负担，把注意力留给目标、关键决策和结果验收。这里借鉴的是系统设计方法，不复制其源码、提示词或界面，也不要求使用 DeepSeek 模型或 DeepSeek Harness。

### 借鉴的原则

- **有请求或授权规则才行动。** 主动工作先观察，再逐步开放执行范围。
- **有结果或需要人介入时再提醒。** 不把每条内部进度都变成用户消息。
- **如实报告状态。** 未完成、失败和需要决策分别说明，不绕过限制来制造成功。
- **先回答“现在需要我做什么”。** 工作台优先展示待处理事项，再提供运行状态与历史。

以上原则参考 DeepSeek 的 [Super Agent 设计思想](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/000-philosophy.md) 与 [监督面板设计](https://github.com/deepseek-ai/dsh-superagent-prototype/blob/main/docs/005-panel.md)。下面是 Jarvis 对这些原则的具体取舍，不代表参考项目的原样实现。

### Jarvis 如何落地

| 设计重点               | 当前做法                                                                                                               |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 对话与执行分离         | 对话模型理解需求并提出任务；Codex 执行已批准的任务。聊天不会等待整个执行过程结束，模型不能批准自己的提案。             |
| 把授权变成明确边界     | 批准绑定任务版本、执行工具、模型选择、专用目录和有效期。重做或恢复需要重新批准，不因一句“继续”沿用未知状态下的旧授权。 |
| 以可检查的交付结束工作 | CLI 返回结果后进入待验收。用户接受后才标记完成，执行成功不等于独立验证通过，也不等于已应用到其他项目。                 |
| 把人工介入集中呈现     | 总览优先列出待批准、待验收、失败和中断任务；任务与交付物页面保留进一步检查的入口。                                     |
| 从小范围主动性开始     | 规则的观察模式只记录到期事件，提案模式只创建待批准任务。当前不会自主检查外部系统或自动批准执行。                       |
| 恢复状态，而非盲目重跑 | 消息和任务持久化。重启后不自动重放可能有副作用的执行，进程状态未知时先要求人工核实。                                   |

当前任务主流程为：

```text
人工建任务 / 对话提案 / 规则提案
              ↓
      待批准 → 排队 → 执行 → 待验收 → 人工接受
                       ↓
                失败、中断或取消
```

长期自主推进、完整跨员工接责、原生权限交互和版本化交付验证仍是后续目标，不能把现有任务队列等同于完整 Super Agent。通知目前也包括规则观察记录，减少无效提醒仍需持续验证。具体实现边界见 [架构说明](docs/architecture.md) 和 [交付状态](docs/status.md)。

## 本地启动

需要 Node.js 22.18 或更高版本。本开发版尚未内嵌运行环境。

```bash
npm ci
npm run build
JARVIS_OPEN=1 npm start
```

Mac 也可双击 `启动Jarvis.command`。服务仅监听 `127.0.0.1:4320`，启动器在浏览器打开一次性登录入口。令牌不写日志，浏览器取得会话后清除地址栏中的令牌。关闭窗口不等于停止服务，在启动终端按 `Ctrl+C` 停止。

首次使用：

1. 在「设置」填写模型服务地址、模型名和 API Key。发送消息时，会将当前会话选取的内容和该员工记忆发送给你配置的供应商。
2. 在「数字员工」创建员工，填写职责并选择执行工具。
3. 创建私聊或群组。模型可以回复或提出任务建议，不能批准任务。
4. 在「任务」检查说明、目录、工具和执行范围，再批准执行。
5. 在「交付物」检查输出并验收。执行成功不等于结果经过独立验证，也不等于已应用到其他项目。

## 云端派单与 Mac 执行

开发分支 `feature/cloud-mac-control` 增加私有云模式，不覆盖 `main`。云端只保存账户、命令信箱和业务快照，Mac 继续持有唯一工作区并执行任务。默认使用新的 `.jarvis-worker/`，不读取已有项目或迁移 `.jarvis/`。

- 无需域名。通过 SSH 本地转发访问，云端只监听 `127.0.0.1:4321`，Mac 本地配置入口默认 `127.0.0.1:4322`。
- 云端密码登录、一次性设备配对和显式撤销。Mac 主动同步，不向公网开放执行接口。
- 派单先排队，再由 Mac 应用。Mac 离线时只能排队和查看旧状态，不能生成新回复。
- API Key、供应商地址、模型名和思考模式在 Mac 本地配置。云端只读展示服务商、模型和配置状态摘要，不接受配置保存请求，也不接收 API Key。
- 新工作区的会话、记忆、任务和文本交付会保存到云端。项目文件、原始 CLI 日志和登录凭据不参与同步。
- 执行结果不明时不自动重放。断线或撤销后停止新启动，并尝试中断在途请求，不能保证外部请求立即停止。

按 [SSH 私有部署指南](docs/cloud-deployment.md) 完成配置。该指南不代表已部署到你的服务器，实际部署需要先核实 SSH 身份和已有服务。[云端架构与故障边界](docs/cloud-architecture.md) 说明状态含义和安全限制。

## 能力与边界

- 总览、任务、数字员工、会话、交付物、设置六个页面。
- 提供 DeepSeek、OpenAI、Anthropic、Gemini、通义千问、Moonshot/Kimi、智谱、豆包与 OpenAI 兼容服务配置。实现 OpenAI 兼容和 Anthropic 原生协议，提供商真实联调须另行完成。
- 主会话和注意力可独立配置模型和密钥。明确 @ 和私聊绕过注意力判断，不绕过执行审批。
- 员工长期记忆由用户维护。每员工消息处理串行，任务有全局和每员工并发限制。
- Codex 使用已登录的本机 CLI，执行目录按任务隔离，采用 `workspace-write` 和不自动批准越界操作的策略。工具默认模型不一定适配你的账号，可在设置中指定 Codex 执行模型。
- Claude Code 可作为员工工具选择，但当前安全适配器尚未完成，因此阻止执行并显示原因，不会替换工具。
- 关注规则可记录到期事件，或生成待人工批准的任务。观察记录不代表已经检查外部系统。
- 重启不自动重放任务。执行中断、未知进程和旧授权必须由你核实后重新批准。

## 数据与安全

默认数据保存在 `.jarvis/`，目录权限 `0700`，数据库、密钥与本机登录文件权限 `0600`。这些文件不进 Git。文件权限不是加密，同一账户下的其他进程仍可能读取数据。

只绑定回环地址不是完整安全措施。API 另有会话身份、Host、Origin 和请求头检查；模型请求拒绝重定向，不向前端或错误日志返回 API Key。密钥文件与数据库摘要不一致时停止模型发送，要求重新填写密钥并保存。

CLI 的 `workspace-write` 不是虚拟机，也不等同于只能读取该目录。不要把秘密放入任务提示词。执行器可能按其账户能力调用外部服务。当前不支持任意项目路径或完整 Git 工作树协调。

若服务异常退出留下锁文件，启动器会拒绝重复启动。先确认旧服务和任务进程均已停止，再移走 `.jarvis/instance.lock` 并重新启动；不要在进程仍运行时删除锁。
